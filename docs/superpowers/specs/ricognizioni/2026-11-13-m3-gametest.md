# Spike: headless GameTest on all four variants

Date: 2026-11-13. Worktree `agent-aebf137cfe8ef64bf`, local throwaway branch `spike/gametest` (commit `9ed588d`, not pushed).

Files next to this report:
- `gametest-spike.patch`: the working tree against main, including the two binary `.nbt` files (apply with `git apply --binary`).
- `mknbt-empty-structure.py`: generator for the empty structure.
- `gametest-spike.partial-notes.txt`: raw notes taken during the spike.

## Answer

**Yes.** On all four variants the vanilla GameTest server runs headless from one Gradle task per variant (`:<variant>:runGameTestServer`), with no client and no display, and the JVM exit code is the number of failed required tests (`System.exit(testTracker.getFailedRequiredCount())`, checked with javap on both versions). Loom's `JavaExec` turns that into a failed Gradle task.

The mock-player frame-state test (`update` then `get`, so `reinforced() == true`) **passes on all four**, but only after a workaround on 1.20.1: on Forge the vanilla `makeMockServerPlayerInLevel()` throws inside Forge.

| Variant | Headless run | Pass: exit / time | Deliberate fail: exit / time | Mock-player state test |
|---|---|---|---|---|
| 1.20.1-fabric | yes | 0 / 16-18 s | 1 / 17 s | passes (vanilla helper passes too, but the sync is only queued; with the embedded-channel helper it is really written) |
| 1.20.1-forge | yes (needs `forge.gameTestServer=true`) | 0 / 27-31 s (56 s first run, world generation) | 1 / 30 s | vanilla helper: **NPE inside Forge**. With our embedded-channel helper: passes |
| 1.21.1-fabric | yes | 0 / 18-19 s | 1 / 15 s | passes, sync really sent to the embedded channel |
| 1.21.1-neoforge | yes (needs `neoforge.gameTestServer=true`) | 0 / 19-21 s | 1 / 18 s | passes, **sync skipped** (mock client has not negotiated the channel) |

All four in one call: `./gradlew --console=plain :1.20.1-forge:runGameTestServer :1.20.1-fabric:runGameTestServer :1.21.1-fabric:runGameTestServer :1.21.1-neoforge:runGameTestServer` took 69 s warm with exit 0. Times are with warm Gradle/Loom caches. The first configuration of the worktree took about 70 s, because ~/.gradle was already populated.

**Main caveat for CI:** an exit code of 0 does not by itself prove that tests ran. A server that does not start the GameTest path, or that starts with zero tests, exits 0 on Forge and NeoForge (details under Pitfalls). CI must also check that the expected number of tests passed.

## Shared design used in the spike (same on all four)

- **Tests**: `src/main/java/com/toxineren/exoframes/gametest/ExoframesGameTests.java`. It has no Stonecutter directives.
  - Tests are plain `Consumer<GameTestHelper>` methods collected in `all()`.
  - They are turned into `TestFunction`s by a `@GameTestGenerator`:
    ```java
    @GameTestGenerator
    public static Collection<TestFunction> generate() { ...
        new TestFunction(NAMESPACE, NAMESPACE + ":" + name, EMPTY_STRUCTURE, 100, 0L, true, test) ... }
    ```
    The 7-argument constructor `(batch, testName, structureName, maxTicks, setupTicks, required, Consumer)` exists with the same signature on 1.20.1 and 1.21.1 (checked with javap on both mojmapped jars). The long constructors differ (10 arguments on 1.20.1, 12 on 1.21.1), so avoid them.
  - Why a generator instead of `@GameTest`: the annotation resolves the template differently per loader.
    - Fabric uses `template` as-is.
    - Forge and NeoForge prefix the namespace from `@GameTestHolder` (a loader annotation, default `minecraft`) and the class name unless `@PrefixGameTestTemplate(false)` is present.
    - `GameTest.templateNamespace()` exists only on Forge and NeoForge.
    - The generator gives the same explicit names everywhere.
  - Test names carry the namespace (`redstone_exoframes:trivial_block`) because the loaders filter generated tests differently: Forge 1.20.1 by the namespace of the **test name**, NeoForge 1.21.1 by the namespace of the **structure name** (their `GameTestRegistry` patches). With both set to `redstone_exoframes`, both filters keep the tests.
  - The class has a public no-argument constructor, which the Fabric entrypoint instantiates.
- **Empty structure**: our own `redstone_exoframes:empty` is an 8x8x8 box of air (palette `[minecraft:air]`, 512 blocks, DataVersion 3465), stored as gzip NBT in **both** of these paths:
  - `src/main/resources/data/redstone_exoframes/structures/empty.nbt` (the 1.20.1 path)
  - `src/main/resources/data/redstone_exoframes/structure/empty.nbt` (the 1.21 path; Mojang renamed the folder)

  The vanilla `StructureTemplateManager` loads it on every loader; 1.21 upgrades it from DataVersion 3465 through DataFixer without complaint. Built-in alternatives:
  - Fabric only: `FabricGameTest.EMPTY_STRUCTURE = "fabric-gametest-api-v1:empty"`, an `.snbt` under `data/fabric-gametest-api-v1/gametest/structures/` in 1.2.15 and `gametest/structure/` in 2.0.5.
  - Forge 47.4.29 and NeoForge 21.1.266: no built-in empty template, so a mod-provided `.nbt` is the only cross-loader option.
- **Mock player**: `platform/GameTestPlayers.mockServerPlayer(helper)` (directives allowed in `platform/`).
  - On `<1.21` it builds the player like vanilla (anonymous `ServerPlayer`, creative, not spectator), but attaches the `Connection` to an `io.netty.channel.embedded.EmbeddedChannel` before calling `placeNewPlayer`. This is what 1.21.1 vanilla already does.
  - On 1.21.1 it calls `helper.makeMockServerPlayerInLevel()`, which exists on both versions (javap) but is `@Deprecated(forRemoval)` on 1.21.1 (compile warning).

### The test bodies

```java
public static void trivialBlock(GameTestHelper helper) {
    BlockPos pos = new BlockPos(1, 1, 1);
    helper.setBlock(pos, Blocks.REDSTONE_BLOCK);
    helper.assertBlockPresent(Blocks.REDSTONE_BLOCK, pos);

    Optional<FrameState> state = Compat.frameState().get(player);
    helper.assertTrue(state.isPresent(), "frame state missing after update");
    helper.assertTrue(state.get().reinforced(), "frame state not reinforced after update");

}
```

### build.gradle.kts (essential lines)

```kotlin
loom {
    runs {
        create("gameTestServer") {          // -> task :<variant>:runGameTestServer, runDir versions/<variant>/run
            server()
            name("GameTest Server")
            ideConfigGenerated(false)
            when (loader) {
                "fabric" -> {
                    property("fabric-api.gametest")
                    property("fabric-api.gametest.report-file", project.layout.buildDirectory.file("gametest/report.xml").get().asFile.absolutePath)
                }
                "forge" -> {
                    forgeTemplate("gameTestServer")
                    property("forge.enabledGameTestNamespaces", project.property("mod.id").toString())
                    property("forge.enableGameTest", "true")
                    property("forge.gameTestServer", "true")      // REQUIRED, see pitfalls
                }
                "neoforge" -> {
                    forgeTemplate("gameTestServer")
                    property("neoforge.enabledGameTestNamespaces", project.property("mod.id").toString())
                    property("neoforge.enableGameTest", "true")
                    property("neoforge.gameTestServer", "true")   // REQUIRED, see pitfalls
                }
            }
        }
    }
}
```

Inside the `runs { create { } }` block, `property("x")` is `RunConfigSettings.property` (it sets a system property). Read Gradle properties with `project.property(...)`. Kotlin also prints deprecation warnings for `name`, `ideConfigGenerated`, `property` and `forgeTemplate` on Loom 1.17: they are Java methods marked deprecated. They still work.

Loom 1.17 also ships `fabricApi.configureTests { }` (`GameTestSettings`), which creates a `gametest` source set and `runGameTest`, eula and cleanup tasks. It is Fabric-only and geared to newer Fabric API (client game tests), so it was not used; one generic `loom.runs` entry covers all four loaders.

## What the planned task should do

### Build

1. Add one `loom.runs.create("gameTestServer")` entry per variant, as shown above. Set the loader's `*.gameTestServer=true` and `*.enableGameTest=true` explicitly, because `forgeTemplate` alone is not enough with `server()`. Keep the namespace filter (`forge.`/`neoforge.enabledGameTestNamespaces=redstone_exoframes`).
2. Make "tests actually ran" part of the task result instead of trusting the exit code. A suggestion, not tried:
   - Set `standardOutput` on the run task to a tee into `build/gametest/server.log`.
   - In `doLast`, require a line matching `All (\d+) required tests passed` with the expected count, and fail otherwise.
   - On Fabric the JUnit XML (`fabric-api.gametest.report-file`) can be checked as well, or used instead.

   This catches three cases that exit 0 with zero tests:
   - Forge started as a normal server without a EULA;
   - NeoForge "No test functions were given!";
   - wrong or missing registration.
3. Delete the run world before each run: a `Delete` task on `versions/<v>/run/world`, which every variant creates. Forge's GameTest server uses the normal persistent `run/world`, so frame-state SavedData accumulates across runs. Mock players get random UUIDs, so this spike's test is not polluted, but future tests would be. A fresh world also makes timings repeatable. The run dir is git-ignored.
4. Keep test code and test structures **out of the shipped jar**. The spike put them in `src/main` (ExoframesGameTests class, two `empty.nbt` files, and the `fabric-gametest` entrypoint in the production `fabric.mod.json`; the Forge and NeoForge listeners are inert in production).
   - Option a, clean: a `gametest` source set that depends on `main`, used only by the run configuration (`source("gametest")` on the run). Its resources hold the `.nbt` files, and on Fabric a separate `fabric.mod.json` in that source set gives a tiny test mod with the `fabric-gametest` entrypoint. On Forge and NeoForge, registration then needs either a second `@Mod`, or a hook in the main mod that the test source set fills. Check how Loom builds `MOD_CLASSES` for an extra source set on Forge and NeoForge; not tried in the spike.
   - Option b, simpler: keep everything in main, but exclude `com/toxineren/exoframes/gametest/**` and `data/redstone_exoframes/structure*/empty.nbt` from `jar`/`remapJar`, and keep the inert listeners. The Fabric `fabric-gametest` entrypoint would then point at a missing class. The module resolves entrypoints in its main initializer, so check that this does not crash a normal production start.
   - Also run `tools/check_jars.sh`. Not run in the spike.

### Platform seam

- `platform/RedstoneExoframesForge` and `platform/RedstoneExoframesNeoForge` each get one `RegisterGameTestsEvent` listener: `event.register(ExoframesGameTests.class)`.
- Fabric gets the `fabric-gametest` entrypoint in `fabric.mod.json`, which needs no Java.
- `platform/GameTestPlayers.mockServerPlayer(helper)` (`<1.21`: EmbeddedChannel-backed mock; `>=1.21`: vanilla) is needed: without it Forge 1.20.1 cannot create a mock player at all, and Fabric 1.20.1 never really sends.
  - The current rules say `platform/` holds the entrypoints, and the shared test package now imports `platform/`. Either accept that for test support, or move the helper into the gametest source set and allow Stonecutter directives there; `tools/check_sources.sh` rule 6 would need the new path.
  - `tools/check_sources.sh` passes with the spike as is (`OK sources`).

`com.toxineren.exoframes.gametest`, directive-free. ### Mock-player coverage gaps to keep in mind

- **NeoForge 1.21.1**: sync send skipped (not negotiated). Covering the packet path would mean marking the mock connection's channels as negotiated (NeoForge network internals) or relying on the existing codec unit tests.
- **Forge 1.20.1 and Fabric 1.20.1/1.21.1**: the packet is written to the EmbeddedChannel. Nothing reads it back; the channel's outbound queue could be inspected if needed.

## Pitfalls hit (summary)

1. **Forge and NeoForge start a normal dedicated server** unless `-D(forge|neoforge).gameTestServer=true` is set: `forgeTemplate("gameTestServer")` combined with `server()` does not carry the template's launch target or props.
   - Forge without a EULA then exits **0** with no tests.
   - NeoForge hangs forever as a normal server.
2. **Exit 0 without tests**: Forge (EULA path) and NeoForge ("No test functions were given!" start failure) exit 0. Only Fabric's MainMixin turns a start failure into `-1`. CI has to check the pass line or the report.
3. **Forge 1.20.1 `makeMockServerPlayerInLevel()` NPE** in `NetworkFilters.injectIfNecessary`: the mock `Connection` has no channel. Fixed by an EmbeddedChannel-backed connection.
4. **Fabric 1.20.1**: the vanilla mock connection silently queues packets, so the send path is not tested unless the EmbeddedChannel mock is used.
5. **NeoForge 1.21.1**: the mock client never negotiates channels, so `NetImpl` skips the sync. The test passes but does not cover the send.
6. **Template naming differs per loader** for `@GameTest` (namespace and class prefix on Forge and NeoForge, raw on Fabric). Use `@GameTestGenerator` with explicit names.
7. **Generated-test filters differ**: Forge 1.20.1 uses the test-name namespace, NeoForge the structure-name namespace. Namespace both.
8. **Structure folder rename**: `structures/` (1.20.1) vs `structure/` (1.21); Fabric's own `.snbt` folder follows the same rename.
9. In the Kotlin `runs { create { } }` block, `property(...)` is the Loom run method, not `Project.property`.
10. `makeMockServerPlayerInLevel()` is `@Deprecated(forRemoval=true)` on 1.21.1 (compile warning only).
11. Forge's GameTest world is the persistent, non-flat `run/world`: the first run is slow and state carries over between runs. Clean it before each run.
