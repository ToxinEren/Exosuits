## Missed (what would mislead a planner)
1. **Fall-damage hook point (C7).** Passengers receive `causeFallDamage` straight from their vehicle (`Entity.causeFallDamage` → passengers), so a mixin or test on `doCheckFallDamage` misses mounted falls. On Forge/NeoForge `LivingFallEvent` (`onLivingFall`, head of `LivingEntity.causeFallDamage`) can cancel or change it first. On NeoForge `mayFly()` also counts the `neoforge:creative_flight` attribute. A fall-immunity feature should hook `causeFallDamage` or `LIVING_HURT` with `is_fall`.
2. **`LIVING_HURT` sees different hits per loader.** Fabric (AF `PlayerAttackInvoker`, `@Inject(method="hurt", at=HEAD)` on `Player`) and Forge (`LivingAttackEvent` from `Player.hurt` @3) fire **before** `Player.hurt`'s `isInvulnerableTo`, `abilities.invulnerable`, `isDeadOrDying` and difficulty scaling. NeoForge (`LivingIncomingDamageEvent`, `LivingEntity.hurt` @81) fires **after** all of them. A creative mock's hit reaches the mod listener on Fabric/Forge but not on NeoForge, and a difficulty-scaled amount differs. Tests must use survival mocks and unscaled sources (cactus), or the three loaders diverge.
3. **`ServerPlayer.isInvulnerableTo` = `super || isChangingDimension()`** (the four). `isChangingDimension` is set by `changeDimension`/cross-level `teleportTo` and cleared only by `hasChangedDimension()`, which is called from the client's move packet. A mock sent to another dimension (for a dimension or End test) stays immune to every hit for the rest of the test, and `LIVING_HURT` does not fire on any loader (it is behind `ServerPlayer.hurt` @0-9).
4. **Forge 1.20.1 `tickNonPassenger` guards `entity.tick()` with `Entity.canUpdate()`** (@44-51), and NeoForge's `EntityTickEvent.Pre` is cancelable. The "level ticks the mock" arithmetic of recipes (b) and (d) holds only if no mod disables them; the dossier listed only the NeoForge one.
5. **The respawned player is a plain `ServerPlayer` with `spawnInvulnerableTime = 60` again** (constructor), with no `isCreative()` override, and it inherits the mock's `connection`. A respawn test must end that protection on the new object too before any damage assertion. The dossier's seam note mentions the plain type but not the fresh 60 ticks.
6. **The NeoForge damage path uses `DamageContainer`.** The i-frame branch sets `Reduction.INVULNERABILITY = lastHurt`, and `invulnerableTime` comes from `getPostAttackInvulnerabilityTicks()` (default 20; `LivingIncomingDamageEvent` listeners can change it). The result is the same as vanilla only while no listener sets these. A NeoForge-side 3c implementation that edits the amount in `LivingIncomingDamageEvent` changes `getNewDamage()`, not the `amount` argument.
7. **C9 exceptions:** the PRE-sample is not "the client's position" for passengers (repositioned by `rideTick` in the level tick), for a spectator with a camera (`ServerPlayer.tick` `absMoveTo(camera)`), or after pistons and teleports. The activity measure must treat these as not walked. The dossier excludes passengers and teleports but not pistons or spectator cameras.
8. **Neo21 `Player.hurt` does not call `scalesWithDifficulty()`** (it calls `DamageScaling.getScalingFunction().scaleDamage`). A mixin targeting that call in `Player.hurt` would apply on Fabric/Forge but fail on NeoForge. Same family: Fo20 `Player.causeFallDamage`'s mayfly branch has an extra `onPlayerFall` call, so ordinal-based injections into these methods differ per loader.
