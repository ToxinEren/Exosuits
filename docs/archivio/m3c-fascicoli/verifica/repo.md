## 3. The step-out

**Constants** `FE:63-68`: `STEP = 1.0`, `PLAYER_HALF_WIDTH = 0.3`, `PLAYER_HEIGHT = 1.8`, `FLOOR_EPSILON = 1.0e-3`. Suit box `SuitSize.standingBox(feet)` = 0.8 × 2.97 (`J/frame/SuitSize.java:101-105`).

**Algorithm** [code]:
1. `exit(ServerPlayer)` (`FE:170-181`): `Placeholders.removeAll` → `returnStowed` → `leaveFrame(player, frames, "left")` → `left.ifPresent(spot -> stepOut(player, spot))`.
2. `restingSpot(player)` (`FE:407-432`) decides where the *frame* goes. (a) `FramePlacement.groundBelow(here, player.position())` (`J/frame/FramePlacement.java:76-90`: the suit box dropped straight down with `Shapes.collide(Direction.Axis.Y, box, level.getBlockCollisions(null, box.expandTowards(0, -depth, 0)), -depth)`, `depth = from.y - level.getMinBuildHeight()`; fluids are not ground; empty if nothing down to the bottom) and `insideBorder` (`:62-64`) → `Where.BELOW`. (b) Else `SafeSpots.last(player)`, any dimension (`server.getLevel(dim)`, skipped if null): `groundBelow` again if `hasChunk`, the remembered point as is otherwise; must be inside the border → `Where.SAFE_SPOT`. (c) Else `Vec3.atBottomCenterOf(overworld.getSharedSpawnPos())`, `groundBelow(…).orElse(spawn)`, border not checked → `Where.SPAWN`. `Why` is `NO_GROUND` or `BORDER`. **No room test and no test for another frame at the spot** (contrast `FramePlacement.place`, `:43-47`).
3. `stepOut(player, spot)` (`FE:318-339`) does nothing if `spot.level() != player.serverLevel()`, or `player.isPassenger()`, or `!SuitSize.standingBox(frame).contains(player.getEyePosition())` (`:321-323`). The player already has vanilla size (`refreshDimensions()` at `:298`), and `AABB.contains` takes the lower bound in and the upper bound out [javap V120, V121]: with standing eyes at 1.62 the step exists only while the feet are less than 2.97 − 1.62 = **1.35** above the frame's feet (the design's "un blocco e un terzo").
4. Directions from `player.getYRot()` (`:325-329`), in order front `(-sin, cos)`, left `(cos, sin)`, right `(-cos, -sin)`, behind `(sin, -cos)`. `candidate = (frame.x + dx*STEP, frame.y, frame.z + dz*STEP)`: always at the height of the frame's feet. The first direction with `standingSpot(…)` present **and** `wayIsFree(…)` wins: `player.teleportTo(level, to.x, to.y, to.z, player.getYRot(), player.getXRot())` (`:335`). None: the player stays.
5. `standingSpot(player, level, candidate)` (`FE:368-393`): `box` = x±0.3, y..y+1.8, z±0.3. Reject if `!level.noCollision(player, box)` (`:371`). `depth = 1.0 + FLOOR_EPSILON`; `drop = Shapes.collide(Axis.Y, box, level.getBlockCollisions(null, box.expandTowards(0, -depth, 0)), -depth)`; reject if `drop <= -depth` (`:374-379`). `feet = candidate.add(0, drop, 0)`; reject if `!FramePlacement.insideBorder(level, feet)`. `standing = box.move(0, drop, 0)`. Hazard test (`:385-388`): any position of `BlockPos.betweenClosedStream(standing.expandTowards(0, -0.5, 0))` whose state has `getFluidState().is(FluidTags.LAVA)` or `is(BlockTags.FIRE)`. Reject if hot or `!level.getEntitiesOfClass(ExoframeEntity.class, standing).isEmpty()` (`:389`).
6. `wayIsFree(player, level, candidate)` (`FE:354-360`): one `AABB` spanning `player.position()` and `candidate` (x and z widened by 0.3; y from the lower of the two to the higher + 1.8) must pass `level.noCollision(player, way)`.

**Game facts the algorithm rests on.** [javap V120, V121, identical bytecode] `CollisionGetter.noCollision(Entity, AABB)`: false for any non-empty shape of `getBlockCollisions(entity, box)`, for a non-empty `getEntityCollisions(entity, box)`, and, with a non-null entity, for a `borderCollision`. `Entity.canCollideWith(other)` = `other.canBeCollidedWith() && !isPassengerOfSameVehicle(other)`; `Boat.canBeCollidedWith()` returns true; `AbstractMinecart` (and on 1.21.1 its superclass `VehicleEntity`) does **not** override `canBeCollidedWith()`, which is false in `Entity`. So a boat inside `box` or `way` rejects the spot, **a minecart does not**: §11's "una barca o un carrello che tocca il giocatore" holds for the boat only [patched jars and shulkers not checked]. `BlockCollisions` uses `CollisionContext.empty()` for a null entity, and `PowderSnowBlock.getCollisionShape` returns `Shapes.empty()` when the context has no entity: the drop of step 5 falls through powder snow. [data V120 `data/minecraft/tags/blocks/`, V121 `tags/block/`] `fire` = fire, soul_fire; `campfires` = campfire, soul_campfire; `portals` = nether_portal, end_portal, end_gateway; fluid `lava` = lava, flowing_lava. [javap V120, V121] `BlockTags.FIRE`, `CAMPFIRES`, `PORTALS` and `Blocks.MAGMA_BLOCK`, `SWEET_BERRY_BUSH`, `WITHER_ROSE`, `POWDER_SNOW` exist under these names on both: the hazard list can stay in `frame/` without directives.

## 10. `tools/check_log.py` and `tools/log_allowlist.txt`

- Line format (`log_allowlist.txt:5-14`; parser `check_log.py:49-87`): `scope | maximum | regex | producer`, split on `" | "`, the regex being everything between the second and the last field. `scope` ∈ {`gametest`, `client`}; `maximum` must be digits ≥ 1 (`:72`); `producer` non-empty. `= NAME regex` defines a macro (`[A-Z_]+`, `:59-64`) expanded textually as `{NAME}` in the rule lines *after* it; an undefined name is an error. A rule is refused if it consists only of wildcard characters or starts or ends with `.*` (`:79`).
- Matching (`check_log.py:110-138`): a record is a level line plus the trace lines that follow (`HEAD` `:36-37`, both the `[logger/]: ` and the `(logger) ` shape; `TRACE` `:39`). It is examined if its level is WARN/ERROR/FATAL and its text matches `exoframe` (case-insensitive), or, **at any level**, if the text matches `com\.toxineren|InvalidInjectionException|MixinApplyError|Mixin apply .*failed` (`:41, :119-121`). Only WARN/ERROR/FATAL records can be allowed, by `compiled.fullmatch(message)` against the first rule that matches (`:123-128`). An INFO line containing `com.toxineren` is therefore always a failure. Per log file: more matches than `maximum` → problem (`:131-133`); no recognised level line → problem (`:134-137`). Exit 1 with problems, 2 for usage or a malformed list.
- Today: macros `UUID`, `TESTREG`, `STAMP` (`:20-22`); eight `gametest` rules (`:26, 29, 31, 33, 36, 38, 40, 45`) and one `client` rule (`:46`). `TESTREG` = `\S*exoframes-registry-test[0-9]+[/\\]redstone_exoframes_frames\.dat`: the folder is `Files.createTempDirectory("exoframes-registry-test")` (`GT:2922`), under `java.io.tmpdir`.
